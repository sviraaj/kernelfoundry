# Flash Attention v1

## Algorithm:

### Forward:
1. Divide full Q, K, V into blocks; such that Br = row_dimension(Qi) = Total Q dimension/ N; N chosen such that; Bc = row_dimension(Kj, Vj) = Total K, V dimension/ M; M chosen such that (see section: How to divide the attention problem across GPU -- thoughts)
2. 
for every Head H
    for j in K, V blocks: K(j), V(j) from HBM
      for i in Q blocks: Q(i)
          m`(i), l`(i) -> from HBM
          score(i,j) = Q(i)trans(K(j)) -> SRAM
          m(i) = max(rowmax(score(i, j)), m'(i)) -> registers
          l(i) = rowsum(e^((si,j + m'(i) - m(i)))) + l'(i) (e^(m(i) - m`(i))) -> registers
          O(i) = O`(i) (e^(-m(i) + m`(i))) + e^((si,j + m'(i) - m(i)))V -> to HBM
          m'(i) = m(i) -> to HBM
          l'(i) = l(i) -> to HBM

    Final O(i) = O(i) * (1/l(i)) -> from HBM to HBM -> Split between blocks again (l(i) is elementwise and can include mask -- diagonal matrix with value duplication)

n warps -- 1 block, n warps -> share mem, registers (usually not the bottleneck?)

### Parameters for GPU RTX 5070:
1. Threads per warp = 32
2. GPC = 5
3. TPC = 24
4. SM = 48
5. Per SM:
   - Tensor cores = 4
   - CUDA cores = 128 FP32
6. Shared memory / L1 per SM = 128KB
7. Register file per SM = 256KB

#### GPU Notes
1. Block runs on an SM (many blocks per SM possible)
   - Threads grouped into warps (32)
   - Warp = scheduling + execution unit
2. Number of blocks depends on how you tile the problem
3. Grid   → divide problem
   Block  → share memory + sync
   Warp   → execute + schedule together
   Thread → do work
   MMA    → accelerate math
   - gridDim  → how many blocks
   - blockDim → how many threads per block


4.
If you want some work to stay on a single SM,
you must put it inside one block

If block is too big (uses too many resources):
→ only 1 block may fit per SM

If small:
→ multiple blocks per SM (higher occupancy)

#### How to divide the attention problem across GPU -- thoughts
1. Inner loop is all chunks of Q,  outer loop is K, V chunks

128 KB shared mem --> divide for K, Q, V, keep row on 1 SM, then number of rows for Q will be shared_mem size / ((4 * size of each number (fp16 is 2)) * d); where d is head dimension, number of K, V rows is number of Q rows
This (occupying full shared mem) forces number of blocks on 1 SM to 1 i.e. only 1 block at a time on 1 SM...
